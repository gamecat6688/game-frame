# Excel 配置与多语言

项目已内置 [excel2pb-config 技能](../.agents/skills/excel2pb-config/SKILL.md)。配置表任务先读取该技能；它包含表结构、批注、外键、类型、多语言及格式检查规则，并已适配当前项目路径。可用 `$excel2pb-config` 显式调用。

## 源文件与生成物

`table/xlsx/` 是配置的维护入口：

| 工作簿 / Sheet | 主要内容 |
|---|---|
| 英雄.xlsx / Hero | 名称、称号、阵营、职业、描述、基础属性、关联技能 |
| 技能.xlsx / Skill | 名称、说明、伤害倍率、触发周期 |
| 装备.xlsx / Equipment | 名称、说明、攻击/生命加成、穿戴等级 |
| 关卡.xlsx / Stage | 关卡/敌人文案、敌人属性、奖励 |
| 成长与挂机.xlsx / Rules | 配置版本、初始资源、升级消耗/成长、挂机速率/上限 |
| I18N.xlsx / I18N | excel2pb 动态文案键及 Cn / Tn / En 翻译 |

前四行依次是字段名、类型、过滤标记、说明，第五行开始写数据。主键使用 `pk int32` 或 `pk string`，客户端和服务端均需的列使用 `cs`，仅服务器需要的秘密内容应使用 `s`。关联字段使用第一行批注声明外键，例如 `SkillID` 的 `fk:Skill.ID`。

Godot 内置类型名不能作为 GDScript 字段名，原型使用 `PortraitColor` 避免 `Color` 冲突。关卡 ID 当前要求从 1 连续排列。原型静态场景预置 6 张英雄卡和 3 张装备卡；新增这两类展示槽位需要同时在 `.tscn` 中编辑，不能运行时自动生成。

当前 Go Runtime 固定读取 `Rules.ID=1`，新档初始阵容为 `[1, 4, 2, 3, 5]`、初始装备为 `[101, 102, 103]`，并将 Hero 表中的所有英雄以 1 级加入新档。修改或删除这些 ID 时需同时调整初始化规则与测试；已有存档不会因新增表记录自动获得新英雄或装备。Go 自定义读取器当前使用单主键映射，采用复合主键或新增索引查询前应先扩展 `tools/templates/golang/`。

运行：

```powershell
./tools/generate.ps1
python tools/format_workbooks.py table/xlsx
```

仅生成配置不会更新已经构建的 Go DLL/服务器：它们通过 `go:embed` 内嵌 `.data`，因此规则变更后应运行完整 `./tools/build.ps1 -Test`。不要手改 `generated/`、`.bytes` 或 `.data`。

`generate.ps1` 默认使用 `.tools/excel2pb.exe`，也可通过 `-Excel2pb` 指定现有可执行文件；它自身不编译 excel2pb，也不执行工作簿格式化。完整构建通过 `tools.local.json` 的 `excel2pbSource`（或 `-Excel2pbSource`）编译锁定版本，随后导出和格式化。格式化必须放在最后一次导出之后，因为 I18N 合并可能重写工作簿。`-SkipTables` 会跳过这整段流程，不能用于验证表格变更。

`tools/create_workbooks.py` 是初始样例的种子脚本，已有工作簿时拒绝覆盖；日常维护直接编辑 Excel。

## 双端产物

excel2pb 的 `Client` 输出生成 Godot protobuf 类型、Model 读取器和 `.bytes`；`Server` 输出生成 Go protobuf 类型、配置读取器和 `.data`。客户端使用 excel2pb 内嵌 Godot 模板；Go 侧用本项目 `tools/templates/golang/` 模板生成显式 `Catalog`，不引入全局可变配置单例。

| 产物 | 客户端路径 | 服务端路径 |
|---|---|---|
| 配置 proto | `contracts/generated/client/` | `contracts/generated/server/` |
| protobuf 类型 | `client/protobuf/generated/table/` | 暂存于 `build/tables/go/internal/generated/`，复制到 `game/internal/generated/` |
| 配置读取器 | `client/config/generated/` | `game/internal/generatedloaders/` |
| 二进制表 | `client/config/data/*.bytes` | `game/data/*.data` |

Go protobuf 先生成到暂存目录，再复制到正式目录，避免 `--go_opt=module` 导致导入路径重复嵌套。保留生成物便于审查；excel2pb 管理的输出目录不要混放相同扩展名的手写文件。项目 `generate.ps1` 的 Go 复制步骤只覆盖现存表，不会清理 `game/internal/generated/` 中的过时副本。删除或重命名表时应检查全部输出，显式删除遗留副本并同步调用方及 I18N 键；业务协议由另一条 `generate_proto.ps1` 流水线生成和清理，不能代替配置表导出。

## 静态 UI 翻译

固定按钮、页签和提示使用 `UI_*` / `ERR_*` 键，在三份 `client/localization/ui.*.po` 中维护。

静态 `.tscn` 直接写 `text="UI_LEVEL_UP"`，由 Godot 控件自动翻译。包含数值的句式仍属于 UI 模板，例如 `UI_STATS`；Presenter 使用语言模板与权威数值格式化，而不是把整个数字句子写入 Excel。

## 动态内容翻译

英雄名、装备名等字段类型为 `i18n`，源表写中文文案。excel2pb 生成例如 `Hero_Name_1`、`Equipment_Name_101` 的稳定键，写入生成数据，并将键合并到 `I18N.xlsx`。

新增文案的流程：

1. 在业务 Excel 增加/修改 `i18n` 字段内容，保持对象主键稳定。
2. 生成一次，获得新增 I18N 键。
3. 在 `I18N.xlsx` 补齐 `Cn`、`Tn`、`En`，再次生成。
4. 完整构建，运行三语场景 smoke，检查长文本。

`GameLocalization` 读取 excel2pb 生成的 `I18NModel`，按 `Cn → zh_CN`、`Tn → zh_TW`、`En → en` 注册 Translation。翻译为空时回退到中文。View/Presenter 不依赖语言列，也不直接查询生成表。

采用 Godot TranslationServer 作为最终解析入口不改变内容来源：固定文案来自 PO，动态文案只来自 excel2pb，源文件没有重复维护。

## 扩展语言与版本

新增语言时扩展 I18N 列、`GameLocalization` 的 locale 映射、PO 资源列表，以及 `.tscn` 中静态语言选项；为需要的字形准备可分发字体。

修改不兼容玩法配置时同步更新 `Rules.Version`，并明确存档迁移方式。当前原型要求版本完全一致，旧版本存档或客户端/服务器版本不一致时拒绝继续，不做静默重置。正式项目需要增加配置版本发布、兼容区间与存档迁移工具。
